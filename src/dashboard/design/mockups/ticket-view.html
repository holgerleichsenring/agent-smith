Mock only · what the list reads

  1. Ticket = (project, ticket id). A ticket belongs to exactly one project. Attempts are the code-pipeline runs of that pair, ordered by run id; scans and pr-review runs are not attempts. Extends FiledWorkRunsReader.
  2. Buckets, one owner each. Needs you = a run waiting for an answer (same gate as RunQueuePlace) or a hand-back. Working = running or queued. Waiting on review = a PR open, approved or changes-requested without a started attempt (PR-keyed review record). Stuck = last attempt failed, same ticket fingerprint, and no person commented, moved or reviewed since. Done = merged or closed.
  3. The strip is the ticket's current series: derive, one cell per spec (executed earlier = dashed), PR. Not the five run beats.
  4. One inbox for tickets. The answer box is PendingQuestionCard. Runs without a ticket (chat, CLI, scans) stay answerable in the run viewer only; the runs list keeps “Waiting for input” as a machine filter that links to the ticket when there is one.

Mock only · what the graph reads

  1. The shape is the code pipeline: FetchTicket → AnalyzeCode → DeriveSpec (cut ↔ ISpecCutReviewer, up to the attempt bound) → SpecHandback or SpecGate → SpecSequence (one master → verify → record block per spec, each spec naming one repository) → CommitAndPR.
  2. Specs not yet started (spec 5 in attempt 4) are drawn from the cut itself, which derivation must publish; today the set exists only in memory until a spec changes state.
  3. Carried specs are the series' executed specs (TicketSeries), shown dashed with $0. Not the prior-run ledger seed, which only fires for step-less specs.
  4. Passes are the master's re-engagements inside one spec block. Each lane needs a recorded pass (event + projection, deduplicated by trail sequence) and the LLM calls stamped with their pass, so a lane can carry its own cost. The return label names the reason the policy re-engaged: verdict red with open steps, steps marked done that the diff does not back, or the acceptance gate unsatisfied.
  5. An answered question resumes the same attempt (the question node). A hand-back ends it; the reply starts the next one. Hand-back cases on main: contradiction (confirmed by a checker from cited lines, expires on foreign commits), scope unassigned (no single repository per spec), series out of step, missing spec.
  6. Spec PRs open per series repository when the series is published and stay open on a failed run, not ready until verified.

Mock only · cost and compute

  1. Cost per spec and pass needs each LLM call stamped with its pass when it is published. Each spec is already its own master step carrying its spec id; only the pass is missing. Derive and PR calls are priced by their pipeline command.
  2. No “kept vs lost” dollars. Nothing ties a model call to a step that survived. What carried over is shown as specs, at $0.
  3. Pod end reason (released at end, released at park, vanished, out of memory) must be written where the sandbox closes, on every backend; today every disposed sandbox is recorded as failed. Sandbox rows need a trail sequence and a unique index so a replay does not double pod-minutes. Reference, browser and probe pods are not counted.
  4. Waiting on you needs one record per park (today one checkpoint row per run, overwritten) plus the hand-back-to-reply gap from the conversation record.
